## 1. 产品概述

Prompt & Skills 收藏站是一个个人专用的静态网站，用于统一保存常用 prompt 和常用 skill。

- 目标用户：本人（唯一使用者）。
- 使用场景：保存常用内容，随时查阅、复制或跳转到对应 GitHub 页面。
- 站点标题：Prompt & Skills。

## 2. 需求背景

原始需求包含两项：

1. 保存常用 prompt：列表页展示标题和建议介绍，点击后展示完整 prompt。
2. 记录常用 skills：列表页展示标题、简介和跳转链接，链接指向该 skill 的 GitHub 页面。

## 3. 已确认的设计决策

| 决策点 | 结论 |
| --- | --- |
| 使用范围 | 仅本人使用，无登录，网站对公网只读 |
| 技术形态 | 纯静态站点：HTML/CSS/JavaScript + 数据文件，无框架、无后端、无数据库 |
| 内容管理 | 每条内容一个 Markdown 文件，随 Git 仓库管理 |
| 发布流程 | 本地编辑 → 推送 GitHub 私有仓库 → 服务器定时拉取并构建 |
| 站点标题 | Prompt & Skills |
| 排序规则 | 先按分类、再按标题拼音升序，前端使用 Intl.Collator('zh') |
| 内容分类 | 用 content 下的子目录组织，分类由构建脚本自动提取，前端按目录名分组展示 |
| 分组交互 | 分组可折叠（默认全展开）、标题吸顶、顶部横条与侧边栏两处分类导航 |
| 主题 | 跟随系统 |
| 访问方式 | HTTP 直出（当前无域名；内容公开只读，无凭证传输） |

## 4. 页面结构与交互

### 4.1 整体布局

单页应用，左右两栏结构：

- 左侧边栏：Prompts 和 Skills 两个导航入口，其下是**当前视图的分类子导航**（点击跳转到对应分组）。
- 右侧内容区：标题与条数、分类快捷跳转横条、按分类分组的瀑布流卡片。
- 移动端：侧边栏收起为抽屉，分类横条随页面滚走，分组标题仍吸顶。

### 4.1.1 按目录分组

prompts 按 `content/prompts/` 下的子目录分组展示，目录名即分组名：

- 分组标题吸顶，右侧显示该组条数，配色按分类名取自固定色板，相邻分组不同色。
- 点击分组标题可折叠或展开，状态在切换视图后保留。
- 顶部横条与侧边栏两处分类导航点击后平滑滚动到对应分组，滚动时自动高亮当前分组。
- 分组顺序沿用拼音升序；没有分类的内容归入「未分类」并排在最后。
- 只有一种分类、且它还是「未分类」时不显示分组标题（Skills 目前即如此）。
- 卡片上不再重复显示分类标签，分类信息保留在详情弹窗中。

### 4.2 Prompts 列表与详情

- 卡片展示标题与简介，简介取 prompt 正文的第一行。
- 点击卡片后弹出详情弹窗，弹窗内展示完整 prompt，并按 Markdown 渲染。
- 弹窗提供「复制原始 Markdown」按钮，复制内容为未经渲染的原始文本。

### 4.3 Skills 列表与详情

- 卡片展示标题与简介，简介来自 frontmatter 的 intro 字段。
- 点击卡片后弹出详情弹窗，弹窗内展示完整简介。
- 弹窗提供「打开 GitHub」按钮，点击后在新标签页打开 frontmatter 的 url 字段。

### 4.4 排序规则

先按分类、再按标题拼音升序排列，同一分类的卡片聚在一起。排序在前端完成，使用 `Intl.Collator('zh')`，不引入额外依赖。

## 5. 内容模型

### 5.1 Prompt

- 文件位置：`content/prompts/` 目录下（含子目录）的 Markdown 文件。
- 标题：文件名（不含扩展名）。
- 正文：完整 prompt，使用 Markdown 格式，整个文件即正文，不写 frontmatter。
- 简介：正文第一行，构建时自动提取。
- 分类：所在子目录名，构建时自动提取；子目录可继续嵌套。

### 5.2 Skill

- 文件位置：`content/skills/` 目录下（含子目录）的 Markdown 文件。
- 标题：文件名（不含扩展名）。
- frontmatter 字段：intro（简介）、url（GitHub 链接）。
- 正文：本期不使用，预留为空。

### 5.3 初始数据

建站时预置 2 条 prompt 与 2 条 skill 示例，用于验证列表、详情、复制和排序链路。示例数据可随时删除。

当前实际内容：12 条 prompt，按决策、学习、解决问题、认识你自己、问清问题 5 个分类组织；2 条 skill。

## 6. 数据管理与发布流程

1. 在本地编辑 content 目录下的 Markdown 文件。
2. 提交并推送至 GitHub 私有仓库。
3. 服务器定时任务拉取最新代码，并执行构建脚本。
4. 构建产物由 nginx 静态服务，页面即时生效。

构建脚本 build.py 为零依赖 Python 脚本，负责读取 content 目录并生成数据文件。定时任务默认每 5 分钟执行一次，作为初始配置，可调整。

## 7. 非功能需求

- 部署环境：Debian 12，需要安装 nginx 和 git，系统自带 Python 3。
- 仓库访问：服务器使用只读 deploy key 拉取私有仓库。
- 兼容性：目标浏览器为现代浏览器（Chrome、Safari、Firefox）。
- 安全边界：无登录、无写入接口，网站对公网只读。

## 8. 验收标准

1. 内容区以瀑布流卡片展示列表，卡片高度随内容变化。
2. 点击 prompt 卡片弹出详情，包含渲染后的完整 prompt 与复制按钮，复制结果为原始 Markdown。
3. 点击 skill 卡片弹出详情，包含简介与「打开 GitHub」按钮，按钮在新标签页打开正确链接。
4. 两个列表均按标题拼音升序排列；prompts 按目录分组，分组顺序同为拼音升序。
5. 点击分组标题可折叠或展开，折叠状态在切换视图后保留。
6. 点击分类导航（顶部横条或侧边栏）滚动到对应分组，滚动时当前分组高亮。
7. 移动端侧边栏为抽屉式，页面可正常浏览与操作。
8. 本地推送后，服务器在一个定时任务周期内完成更新。
9. 加载中、空列表、数据读取失败三种情况都有明确提示，失败时可直接重试。
10. 键盘可完成全部操作：Tab 在导航、卡片、弹窗间移动且焦点可见，Esc 关闭弹窗与抽屉。
11. 桌面端与移动端布局正常，移动端侧边栏为抽屉式，点击区域足够大。

## 9. 范围外与后续优化

- 搜索与标签：本期不做，待内容量增长后按需增加。
- 分类：已支持，通过 content 下的子目录组织，构建脚本自动提取，前端按目录分组展示。
- 登录、HTTPS 与域名：获得域名后补充 HTTPS 证书；登录本期不需要。

## 10. 待确认事项

- GitHub 仓库创建：本机未安装 GitHub CLI，需要手动在 GitHub 创建私有仓库；仓库名与目录名一致（my-library）。
- GitHub 用户名：需要用户提供，用于配置服务器 deploy key。
