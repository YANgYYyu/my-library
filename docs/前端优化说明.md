# 前端优化说明

本次改动只涉及表现层与交互层，不改数据模型、不改构建产物结构、不引入第三方依赖。

## 改动文件

### public/style.css

| 改动 | 目的 |
| --- | --- |
| 新增 `--accent-soft`、`--radius-sm/--radius/--radius-lg`、`--ease` 三个令牌 | 让圆角、缓动、主色浅底有统一取值，避免各处写死；颜色仍沿用原有主色与中性色体系 |
| 新增全局 `:focus-visible` 焦点环 | 之前只有卡片有焦点样式，键盘操作时其余控件没有任何提示 |
| 新增 `[hidden] { display: none !important }` 与 `.sr-only` | 前者避免以后给元素加 `display` 后 `hidden` 失效；后者给屏幕阅读器提供不可见播报区 |
| 内容区加 `max-width: 1180px`、标题下加分隔线、字号字重重新排布 | 宽屏下卡片不会被拉得过宽；标题、条数、卡片标题、简介、标签形成明确的主次层级 |
| 卡片内边距与行高调整，标题加 `font-weight: 600` | 用字重与留白区分主次，而不是靠新增颜色 |
| 卡片 hover / active 状态补充 | 之前只有 hover 改边框与阴影，缺少按下反馈；`translateY(-1px)` 幅度很小，不喧宾夺主 |
| 新增骨架屏、空态、错误态样式 | 三种此前完全缺失的状态现在有统一的中性面板，不引入新的告警色 |
| 弹窗内 Markdown 正文排版（p / h1-h3 / ul / ol / blockquote / hr / a） | 弹窗正文此前完全依赖浏览器默认样式，层级与间距混乱 |
| 按钮补齐 hover / active / disabled 三态，最小高度 38px | 统一反馈，保证点击区域 |
| 关闭按钮、汉堡按钮、侧边栏关闭按钮扩到 36–44px | 原尺寸低于可点击区域推荐值，移动端尤其难点 |
| 新增 `@keyframes fade-in / modal-in / pulse` 与 `prefers-reduced-motion` 兜底 | 过渡控制在 0.15–0.25s；系统开启减弱动效时全部关闭 |
| 移动端抽屉用 `visibility: hidden` 收起 | 抽屉收起后仍能被 Tab 聚焦，是键盘可达性缺陷；纯 CSS 解决，不需要 `inert` |

### public/app.js

| 改动 | 目的 |
| --- | --- |
| `buildColumns()` 抽出，`renderMasonry` 与 `renderSkeleton` 复用 | 消除重复的建列代码，没有新增抽象层 |
| 新增 `renderSkeleton` | 加载态。骨架延迟 0.18s 淡入，本地数据秒回时不会闪一下 |
| 新增 `renderEmpty` | 空态。列表为空时给出说明与补内容的做法，而不是只剩「0 条」 |
| 新增 `renderError` + 重试按钮 | 错误态。区分 `file://`、404 与其他 HTTP 错误；重试期间按钮 `disabled`，这是 disabled 状态唯一的真实使用场景 |
| `load()` 与 `init()` 拆分，`bindUI()` 移到加载前 | 重试不会重复绑定事件；加载失败也能正常操作导航 |
| 新增 `announce()` 与 `#status` 播报区 | 视图切换时播报「Prompts，共 N 条」。原先 `aria-live` 挂在整个列表上，会在切换时朗读全部卡片 |
| `openModal` / `hideModal` 增加焦点管理，新增 `trapFocus` | 弹窗打开时锁定滚动、焦点移到关闭按钮，Tab 在弹窗内循环，关闭后焦点归还触发它的卡片 |
| `setDrawer` 增加焦点转移与 `wasOpen` 判断 | 抽屉打开时焦点进入抽屉，收起时归还汉堡按钮；避免未打开时也抢焦点 |
| 新增 `selectView`，导航项设置 `aria-current="page"` | 当前视图对屏幕阅读器可识别 |
| 卡片结构改为 `article > h3 > button.card-link` | 原来是 `<button>` 里嵌 `<h3>` 与 `<p>`，不符合 HTML 内容模型；新结构整卡可点击、Tab 只有一处停留、保留标题语义 |
| 卡片无 `intro` 时不再插入空节点 | 避免出现无内容的空段落占位 |

### public/index.html

| 改动 | 目的 |
| --- | --- |
| 侧边栏移除 `aria-hidden="true"` | 桌面端侧边栏始终可见，加 `aria-hidden` 会让屏幕阅读器直接跳过导航；移动端改由 `visibility: hidden` 移出可访问树 |
| 导航项增加 `aria-current="page"` | 标记当前视图 |
| 新增 `#status` 隐藏播报区 | 承载视图切换播报 |
| `#masonry` 去掉 `aria-live`、加 `tabindex="-1"` | 不再整体朗读列表；重试成功后可把焦点落回内容区 |
| `#modal-box` 增加 id | 供焦点陷阱定位 |

### tests/test_frontend.py（新增）

零依赖静态检查，拦截重构中最容易失手的两类改动：

- `app.js` 用到的 `#id` 选择器必须存在于 `index.html`（含 `aria-labelledby` 等引用）。
- `app.js` 生成或切换的 class 必须在 `style.css` 中有样式；另有 CSS 括号配对与自定义属性声明检查。

### docs/开发文档.md、docs/产品设计文档.md

同步第 7 节前端设计（新增 7.7 状态与反馈、7.8 可访问性）、第 9 节测试清单，以及产品验收标准第 7–9 条。

## 验证

- `python3 build.py`：构建通过，12 prompts / 2 skills。
- `python3 -m unittest discover tests`：28 项全部通过。
- `node --check public/app.js`：语法通过。
- 用最小 DOM 桩在 Node 里执行 `app.js`（临时脚本，已删除），覆盖：列表渲染与卡片结构、弹窗开合与焦点归还、Tab 焦点循环、视图切换与 `aria-current`、空态、错误态与重试恢复。
- 浏览器手工核对：启动 `bash scripts/restart.sh` 后访问 `http://localhost:8001`。

## 说明

页面没有表单，因此「表单校验提示」一项无对应改动；相关要求落到错误态提示与键盘可达性上。
