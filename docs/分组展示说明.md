# 按目录分组展示说明

本次改动只涉及表现层与交互层，**不改数据模型、不改构建产物结构、不引入第三方依赖**。
`build.py` 与 `public/data.json` 一行未动，服务器定时任务无需任何干预。

## 背景

`content/prompts/` 下的子目录（决策、学习、解决问题、认识你自己、问清问题）在
`data.json` 里已经是每条内容的 `category` 字段，但前端只把它当成卡片底部的一个小标签，
分组信息等于白扔了。本次把它用起来：内容按目录名分组展示。

## 改动文件

### public/index.html

| 改动 | 目的 |
| --- | --- |
| 侧边栏新增 `<nav id="nav-groups">` | 承载当前视图的分类子导航，不用 JS 拼整块结构 |
| 内容区新增 `<nav id="group-nav">` | 顶部分类快捷跳转横条 |
| `#masonry` 改名为 `#groups`、容器语义从「瀑布流」变为「分组列表」 | 分组后瀑布流下沉到每个分组内部，外层容器不再是瀑布流本身 |

### public/style.css

| 改动 | 目的 |
| --- | --- |
| 新增 `--sticky-bg`、`--group-nav-h`、`--topbar-h`、`--group-hue`、`--group-accent`、`--group-accent-soft` | 吸顶底色、两处吸顶偏移量、分组配色各自成为可调令牌 |
| 新增 `.group-nav` 与 `.group-chip` | 顶部分类横条。横条用负边距做通栏，否则卡片会从两侧 padding 里穿过去 |
| 新增 `.group` / `.group-header` / `.group-toggle` / `.group-chevron` / `.group-name` / `.group-count` | 分组标题。`position: sticky` 让长列表滚动时始终看得到当前分组 |
| 新增 `.nav-groups` / `.nav-subitem` 系列 | 侧边栏分类子导航，与顶部横条共用一套高亮逻辑 |
| 删除 `.card-tag` | 分组标题已写明分类，卡片上再挂一个同名标签是重复噪音 |
| 移动端 `.group-nav` 改为 `position: static` | 顶部已有汉堡按钮，再叠一条吸顶横条会占掉近一半可视高度；移动端只保留分组标题吸顶 |

### public/app.js

| 改动 | 目的 |
| --- | --- |
| 新增 `groupItems` / `isGrouped` / `hueFor` | 分组、是否值得分组、配色。全是纯函数，可被单测直接调用 |
| 新增 `renderGroupNavs` / `renderGroups` / `setCollapsed` | 分组渲染与折叠。折叠状态按视图分别存在 `state.collapsed` 里，切换视图与窗口缩放后保留 |
| 折叠时不建瀑布流，展开时补建 | 元素 `hidden` 时 `offsetHeight` 为 0，「放进最短列」会把卡片全塞进第一列 |
| 新增 `scrollToGroup` / `syncActiveGroup` / `measureStickyTop` | 点击分类滚动到分组；滚动时两处导航同步高亮。吸顶偏移量从渲染出的分组标题读 `top` 计算值，不在 JS 里重复写断点 |
| scroll 监听以 rAF 节流 | 滚动高亮是最容易写成性能陷阱的地方 |
| `renderState` 里调用 `clearGroupNavs` | 空态与错误态不该残留上一次的分类导航 |
| `renderMasonry` / `buildColumns` 改为接收容器参数 | 瀑布流下沉到分组内部后，不再固定渲染进 `#groups` |

### tests/test_grouping.py（新增）

从 `app.js` 原文中抽取四个纯函数，拼上最小样板交给 node 执行后断言。
中文排序依赖 `Intl.Collator('zh')`，Python 标准库没有对等实现，在 Python 侧重写排序规则

## 设计取舍

- **分组在前端做，不在 build.py 里做**：分组顺序要跟卡片排序一样按拼音，
  Python 标准库没有中文排序；`data.json` 保持「文件顺序 + 原始字段」，
  排序与分组的策略变动就不需要重新构建。
- **分组内各自分列，不跨分组混排**：否则一个分组的卡片会被另一个分组截断，
  分组边界失去意义。代价是小分组（如只有 1 条）在 3 列布局下会显得空。
- **未分类沉到最后**：空字符串在 `Intl.Collator('zh')` 里比较最小，会排到最前面，
  这是最不符合直觉的位置，需要显式挪到末尾。
- **色板固定 8 色 + 顺延避让**：按目录名哈希取色保证同名分类颜色稳定，
  但 5 个分组在 8 色里撞色的概率不低，因此撞色时顺延到下一个未被占用的色相。

## 审查后补充的修复

本次改动上线前做了一轮对抗性审查，修掉 4 个缺陷，细节见 `docs/对抗性审查报告.md`：

| 缺陷 | 修复 |
| --- | --- |
| P0 瀑布流分列失效：`renderMasonry` 在 section 挂进文档前被调用，卡片全堆第一列 | 先挂载再建瀑布流 |
| P1 分组配色对比度：浅色主题 4 个色相低至 2.25:1 | 新增 `--group-accent-text`，文字与装饰分两档明度 |
| P2 分组名没有标题语义，读屏用户失去按标题跳转 | 改为 `h3 > button`，卡片标题相应降为 h4 |
| P2 resize 无条件重建列表（移动端地址栏收放即触发） | 只有布局指纹变化时才重建 |

## 验证

- `python3 build.py`：构建通过，12 prompts / 2 skills。
- `python3 -m unittest discover tests`：43 项全部通过（分组逻辑 12 项 + 渲染链路 12 项）。
- `node --check public/app.js`：语法通过。
- `tests/dom_stub.js` 最小 DOM 桩覆盖 12 项：分组顺序与条数、标题层级、两处导航、卡片分列、
  折叠与展开（含折叠时懒建瀑布流）、点击分类跳转、滚动高亮、resize 重建时机、平铺视图、切换视图。
  把 P0 的修复回退后这套测试会立刻报错，敏感度已反向验证。
- HTTP 冒烟：`bash scripts/restart.sh` 后四个资源均返回 200。
- 交互与视觉表现仍按产品设计文档第 8 节的验收标准手工核对。
