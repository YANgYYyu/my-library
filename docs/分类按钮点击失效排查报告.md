# 「认识你自己」「问清问题」按钮点不动 —— 排查报告

日期：2026-09-04　影响范围：`public/app.js`（分类横条 chip 的跳转）

## 结论速览

四个假设**全部排除**：按钮没有被禁用、没有被遮挡、事件绑定正常、控制台零报错。

真正的原因是**滚动被物理钳制**：文档末尾没有余量，最后几个分组在几何上就滚不到吸顶位置，
`window.scrollTo` 被浏览器静默截断；叠加 `syncActiveGroup` 把高亮硬写成最后一组，
于是点击后「页面不动 + 高亮不变」，观感上就是按钮失灵。

## 一、四个假设逐一排查

| 排查项 | 结论 | 证据 |
| --- | --- | --- |
| disabled / 条件渲染 / 状态判断 | **排除** | chip 与分组标题都是 `<button type="button">`，无 `disabled`；真实鼠标点击在 1440×900、1440×780、420×820 三个视口下 `可点=Y` |
| 遮挡 / z-index / pointer-events | **排除** | 用 `elementFromPoint` 取按钮中心点的顶层元素，桌面 5 个 chip + 5 个侧栏项全部返回自身；`.group-nav`(z-index 20) 与 `.group-header`(z-index 10) 是设计意图，不存在互相覆盖 |
| 事件绑定失效 | **排除** | `renderGroupNavs` 在 `createElement` 后直接 `addEventListener('click', ...)`，无事件委托、无父级 `stopPropagation`；同批绑定的折叠按钮 5/5 全部生效，证明绑定时机没问题 |
| 控制台报错中断 | **排除** | 三个视口全程 `console error` 与 `pageerror` 均为 0 |

## 二、根本原因

### 2.1 滚动距离不够（主因）

桌面 1440×900 下：文档高 1330、视口 900，**最大可滚动距离只有 430px**。

| 分组 | 标题在文档中的位置 | 顶到吸顶位需要滚动 | 实际能滚 |
| --- | --- | --- | --- |
| 解决问题 | 166 | 97 | 97 ✓ |
| 决策 | 378 | 309 | 309 ✓ |
| 认识你自己 | 590 | 521 | **430（被钳制）** ✗ |
| 问清问题 | 779 | 710 | **430（被钳制）** ✗ |
| 学习 | 990 | 921 | **430（被钳制）** ✗ |

`scrollToGroup` 算出的目标值超过了 `scrollHeight - innerHeight`，浏览器静默截断到 430。
**一旦页面已经在底部，点击「问清问题」目标值和当前值都是 430 —— 位移为 0，页面纹丝不动。**

### 2.2 高亮被硬写成最后一组（放大器）

`syncActiveGroup` 里有一段兜底：

```js
const atBottom = window.innerHeight + window.scrollY >= doc.scrollHeight - 4;
if (atBottom) activeKey = state.groups[state.groups.length - 1].key;
```

被钳制后页面必然停在底部，于是**无论点哪个分类，高亮都跳到「学习」**。
用户看到的是：点了 → 页面没动 → 高亮也没变 → 判定「这个按钮坏了」。

### 2.3 亚像素导致高亮错一位（附带的老问题）

`scrollToGroup` 正好滚到 `stickyTop + 8`，而判定条件是 `rect.top <= stickyTop + 8`。
浮点误差让刚滚到的分组差 0.x 像素落选，高亮停在上一组 —— 点「决策」却高亮「解决问题」。

## 三、最小改动修复

只动 `public/app.js`，CSS 零改动。

| # | 改动 | 解决 |
| --- | --- | --- |
| 1 | 新增 `fitScrollTail()`，按缺口给 `#groups` 补尾部 `padding-bottom`（只在真的不够时补） | 2.1 |
| 2 | 在 `renderGroups` / `setCollapsed` / resize 后调用它 | 2.1 |
| 3 | `syncActiveGroup(forcedKey)`：点击时直接用被点的 key；删掉 `atBottom` 硬写；判定加 1px 容差 | 2.2 / 2.3 |
| 4 | 新增 `scrollChipIntoView()`：高亮变化时把当前 chip 横向带回可视区 | 窄屏看不见就点不到 |

关键实现：

```js
function fitScrollTail() {
  const container = $('#groups');
  if (!container) return;

  container.style.paddingBottom = '0px';           // 先归零再量，否则会累积
  const sections = [...state.sections.values()];
  const last = sections[sections.length - 1];
  if (!last) return;

  const docTop = window.scrollY + last.getBoundingClientRect().top;
  const need =
    docTop - stickyTop - 8 + window.innerHeight - document.documentElement.scrollHeight;
  if (need > 0) container.style.paddingBottom = Math.ceil(need) + 'px';
}
```

补白量是一次算准的：设 padding 后 `scrollHeight` 线性增加 `need`，新的 `maxScroll`
正好等于 `docTop - stickyTop - 8`。且 `docTop <= scrollHeight` 恒成立，
所以 `need < innerHeight`，不会出现一屏以上的空翻。

## 四、为什么以前没暴露

- 修复前所有分组的点击都「有位移」，只是末尾几个到不了位，容易被当成设计如此。
- 只有当用户**先滚到底再点分类**时才会退化成零位移，是最容易被忽略的操作顺序。
- `atBottom` 兜底掩盖了高亮错误：高亮看起来「有变化」（跳到最后一组），反而更像正常工作。
