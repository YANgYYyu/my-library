## 1. 目标与范围

本网站是一个个人专用的静态站点，用于保存常用 prompt 和常用 skill。

本期范围：

- 实现 Prompts 与 Skills 两个列表，展示方式为瀑布流卡片。
- 实现卡片点击后的详情弹窗、复制与跳转功能。
- 实现按分类分组展示：分组标题、折叠、分类导航与滚动高亮。
- 实现按分类与标题拼音升序的排序、跟随系统的主题和移动端抽屉侧边栏。
- 实现搜索、单条内容深链与 Markdown 渲染白名单消毒。
- 实现内容子目录分类，分类由构建脚本从目录结构自动提取。
- 实现零依赖构建脚本与 Debian 12 服务器部署。

本期不做：

- 登录、后端、数据库。
- 标签。
- HTTPS 与域名（待获得域名后补充）。

## 2. 技术选型

| 部分 | 选型 | 说明 |
| --- | --- | --- |
| 前端 | 原生 HTML/CSS/JavaScript | 无框架、无构建工具；两个本地 vendor 库（marked、DOMPurify） |

| Web 服务器 | nginx | 服务构建产物，HTTP 直出 |
| 内容存储 | Git 仓库（GitHub 私有仓库） | 本地编辑后推送 |

## 4. 内容格式规范

### 4.1 通用规则

- 每条内容一个 Markdown 文件。
- **标题一律取自文件名**（不含扩展名），文件里不再写 `title` 字段。
- 文件编码为 UTF-8。
- 可用子目录对内容分类，子目录名即 `category`，允许继续嵌套（如 `学习/写作`）。
  构建脚本递归采集分类根目录下的所有 Markdown 文件；文件直接放在分类根目录时 `category` 为空字符串。
- 内容 ID 取相对于分类根目录的路径（不含扩展名，分隔符统一为 `/`），例如 `决策/双向钢人论证`。
  因此不同分类下的同名文件不会互相覆盖。

### 4.2 Prompt 文件

位置：`content/prompts/`。

**不使用 frontmatter**，整个文件即 prompt 正文。文件开头的 `---` 会被视为残留的
frontmatter 并导致构建报错。

- 标题：文件名（不含扩展名）。
- 正文：完整 prompt，使用 Markdown 格式。
- 简介：正文的第一行，去除首尾空白与行首的 Markdown 标题标记（`#`）后由构建脚本提取。
  例如 `# Role：人生设计师` 会作为 `Role：人生设计师` 显示在卡片上；正文本身不变。
  正文为空时，简介为空字符串。

示例（文件 `content/prompts/翻译助手.md`）：

```markdown
你是一名专业的翻译。请将用户提供的中文翻译为英文，保留术语准确。
```

### 4.3 Skill 文件

位置：`content/skills/`。

因为简介无法从文件名推导，skill 仍保留 frontmatter。

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| intro | 是 | 简介，一句话说明这个 skill 做什么、什么时候用 |
| url | 否 | 上游仓库页面链接；自研或本地 skill 没有链接时可省略 |

- 标题：文件名（不含扩展名）。frontmatter 里即使写了 `title` 也会被忽略。
- 正文：frontmatter 之后的内容，即 skill 的用法说明，会在详情弹窗里渲染并支持复制。
  站内不做外链跳转，因此原文里 `references/*.md` 这类相对链接一律改为保留路径原文，
  再把对应文件内容内联到文末「附录」小节，保证单文件自洽、不出现失效链接。
- 从本地 `SKILL.md` 迁移时，`intro` 取 frontmatter `description` 的第一句；`url` 没有
  可确认的上游地址时省略，不在站内伪造链接。
- 参考文件按体积处理：个人 skill 的 `references/*.md` 通常内联；钉钉系列 skill 的
  `references/` 合计约数 MB，不内联，正文中的相对链接改为「文本（路径）」，避免点击 404。
  `scripts/`、`assets/`、`evals/` 与非 Markdown 参考文件一律不内联。

示例（文件 `content/skills/开发协作/grilling.md`）：

```markdown
---
intro: 按决策树分轮提问，每轮先给推荐答案再等回复，用于压力测试想法与设计。
url: https://github.com/mattpocock/skills/tree/main/skills/productivity/grilling
---

# Grilling

Interview the user relentlessly until you reach a shared understanding.
```

### 4.4 Skill 的两种存放位置

同一个 skill 可能同时存在于两处，用途不同，互不覆盖：

| 位置 | 作用 | 是否入库 |
| --- | --- | --- |
| `~/.workbuddy/skills/`、`~/.agents/skills/` | agent 运行时加载的可执行 skill，改动会直接影响 agent 行为 | 否（家目录） |
| `content/skills/<分类>/` | 本站的展示副本，供浏览与复制 | 是 |

从本地 skill 迁移到本站时只复制内容，不改动、不删除原始文件；两者此后独立演进。

## 5. 数据接口

构建脚本输出 `public/data.json`，结构如下：

```json
{
  "prompts": [
    {
      "id": "解决问题/第一性原理",
      "title": "第一性原理",
      "category": "解决问题",
      "intro": "我想解决的问题是：【填写你的问题】。",
      "body": "我想解决的问题是：【填写你的问题】。\n\n请用第一性原理把它拆回最底层。"
    }
  ],
  "skills": [
    {
      "id": "开发协作/grill-me",
      "title": "grill-me",
      "category": "开发协作",
      "intro": "用连续追问把方案或设计逐层拆到没有待定项，动手前先找出隐藏假设与漏洞。",
      "url": "https://github.com/mattpocock/skills/tree/main/skills/productivity/grill-me",
      "body": "# Grill Me\n\n## What to do\n"
    }
  ]
}
```

字段说明：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | string | 相对分类根目录的路径，不含扩展名（如 `决策/双向钢人论证`） |
| title | string | 标题，取文件名（不含扩展名），与所在目录无关 |
| category | string | 分类，取自子目录名；无分类时为空字符串 |
| intro | string | 简介（prompt 为正文第一行去掉 Markdown 标题标记，skill 为 frontmatter 的 intro） |
| body | string | 完整正文（prompt 为整个文件，skill 为 frontmatter 之后的内容） |
| url | string | skill 的上游仓库链接，可为空字符串（prompt 无此字段） |

`data.json` 保持文件读取顺序；排序与分组均由前端完成。

## 6. 构建脚本设计

`build.py` 使用 Python 3 标准库，不引入第三方依赖。

执行动作：

1. 递归遍历 `content/prompts/` 下的所有 Markdown 文件（含子目录）。
2. 递归遍历 `content/skills/` 下的所有 Markdown 文件（含子目录）。
3. prompt 直接以整个文件作为正文，标题取文件名；skill 解析 frontmatter 取 `intro` 与 `url`。
4. 按第 5 节结构生成数据，`category` 取自所在的子目录名。
5. 将结果写入 `public/data.json`，编码为 UTF-8，不做 ASCII 转义。

prompt 规则：

- 不使用 frontmatter。若文件开头存在 `---` 包围的字段块，视为残留格式并报错。
- 简介取正文第一行（跳过开头的空行），并去掉行首的 Markdown 标题标记 `#`。

skill 的 frontmatter 解析规则：

- 文件前两行必须为 `---`，否则报错并跳过该文件。
- `键: 值` 的键与值之间以英文冒号加一个空格分隔。
- 未知键忽略（包括 `title`）；缺失 `intro` 时报错并跳过该文件，`url` 可省略。

失败与告警规则（出现任一条时不写 `data.json`，返回退出码 1）：

- 任何文件解析失败，都会在 stderr 输出该文件路径与原因。
- 内容 ID 重复时报错。ID 为相对路径，正常情况下不会重复。
- `content/` 目录不存在时报错。
- `content/prompts/` 与 `content/skills/` 都不存在时报错。
- 某个 kind 目录存在但目录下没有任何 Markdown 文件时报错。

## 7. 前端设计

### 7.1 页面结构

`index.html` 包含：

- 侧边栏：站点标题「Prompt & Skills」、Prompts 与 Skills 两个导航入口、当前视图的分类子导航、移动端关闭按钮。
- 内容区：标题与条数、搜索框、分类快捷跳转横条、按分类分组的瀑布流卡片容器 `#groups`。
- 弹窗：详情弹窗容器，包含关闭按钮、正文区和操作按钮。
- 移动端汉堡按钮：位于页面左上角，点击后滑出侧边栏。

### 7.2 分组展示

- 内容按 `category` 分组，分组名取子目录名，嵌套目录显示为 `学习 / 写作`。
- 分组顺序沿用拼音升序，与卡片排序同一套 `Intl.Collator('zh')`；没有分类的内容统一归入
  「未分类」并排在最后。只有一种分类、且它还是「未分类」时不显示分组标题，直接平铺。
- 分组结构为 `section.group > header.group-header > h3.group-heading > button.group-toggle`
  加一个分组内瀑布流容器。
- 瀑布流必须在 section 挂进文档之后再建，且折叠时不建：脱离文档或 `hidden` 的元素
  `offsetHeight` 恒为 0，「放进最短列」会把整组卡片堆进第一列。展开时再补建。
  标题按钮带 `aria-expanded` 与 `aria-controls`，点击折叠或展开；折叠状态按视图分别保存，
  切换视图与窗口缩放触发重建后仍然保留。
- 折叠时不渲染该分组的瀑布流：元素不可见时读不到高度，卡片会被全塞进第一列，展开时再补建。
- 分组配色取自 8 色固定色板，按分类名哈希选色并顺延避让，保证相邻分组不同色；
  色相写入行内 `--group-hue`，深浅两套配色各配一套明度。
- 两条分类导航：内容区顶部横条 `#group-nav` 与侧边栏子项 `#nav-groups`，由 `renderGroupNavs`
  按当前视图生成。点击后平滑滚动到对应分组，目标分组若处于折叠状态会先展开。
- 滚动时用 `syncActiveGroup` 标记当前分组，两处导航同步高亮；滚到页面底部时高亮最后一个分组。
  scroll 监听以 rAF 节流，并遵循 `prefers-reduced-motion`（关闭平滑滚动）。
- 分组标题吸顶，卡片从标题下方划过。吸顶位置由 CSS 变量决定：桌面端为 `--group-nav-h`
  （顶部横条高度），移动端为 `--topbar-h`（汉堡按钮占位，横条在移动端不吸顶）。
  JS 用 `measureStickyTop()` 从渲染出的分组标题读 `top` 计算值，不在 JS 里重复写断点。
  `--group-nav-h` 改值时必须保证横条实际高度与之一致，否则两条吸顶条会互相压住。

- 窗口缩放只在布局指纹 `columnCount() + '|' + isDrawer()` 变化时才重建列表。
  移动端地址栏收放与软键盘弹起都会触发 resize，此时列数与抽屉断点都没变，
  重建只会造成跳动并丢掉焦点。指纹必须包含抽屉断点，否则跨越 767px 时会漏掉收起抽屉。

### 7.3 瀑布流

- 不使用第三方库。
- 页面加载后按容器宽度计算列数：桌面 2 至 3 列，移动端 1 列。
- 分组展示时，每个分组各自分列，卡片不会跨分组混排；平铺时对整份列表分列。
- 同一列内按拼音排序后的顺序依次放入当前高度最短的列。
- **批量测量**：先把所有卡片放进第一列，等一次布局完成后统一读取 `offsetHeight`，
  再清空并按累计高度重新分配到最短列。避免每插一张卡就读一次高度，触发 N 次强制重排。
- 卡片高度由内容自然撑开，不截断、不等高。
- 卡片不再展示分类标签（分组标题已写明分类），分类信息保留在详情弹窗中。
- 卡片结构为 `article.card > h4.card-title > button.card-link`，标题按钮用伪元素铺满整张卡片：
  整卡可点击，Tab 焦点只有一处，焦点环显示在整张卡片上。卡片标题取 h4，位于分组标题 h3 之下。

### 7.4 排序规则

- 先按 `category` 拼音升序，同分类内再按 `title` 拼音升序，使用 `Intl.Collator('zh')`。
- 这样同一分类的卡片在瀑布流中会聚在一起。
- Prompts 与 Skills 两个列表分别排序。

### 7.5 详情弹窗

Prompt 弹窗：

- 标题下方展示分类标签，无分类时隐藏。
- 使用 marked 将正文渲染为 HTML，再由 DOMPurify 按白名单过滤后写入 `innerHTML`。
- 提供「复制原始 Markdown」按钮，复制内容为 `body` 原文，而非渲染后的 HTML。
- 提供「复制链接」按钮，复制该条内容的深链。

Skill 弹窗：

- 展示 `intro` 简介。
- 正文非空时渲染 `body`，并提供「复制原始 Markdown」按钮，复制内容为 `body` 原文。
- 有 `url` 时提供「打开 GitHub」按钮，点击后以新标签页打开；自研 skill 没有链接时不显示该按钮。
- 无论有没有正文或链接，都提供「复制链接」按钮。

复制使用 `navigator.clipboard.writeText`。浏览器不支持剪贴板 API 时，降级为选中文本复制。

消毒白名单只允许 Markdown 常见标签（段落、标题、列表、引用、代码、表格、链接、图片等）
和 `href` / `src` / `alt` / `title` 属性；`style`、事件属性和 `data-*` 一律移除。
DOMPurify 未加载时降级为纯文本，不会退回未消毒的 `innerHTML`。

### 7.6 主题

- 使用 CSS 自定义属性定义深色与浅色两套配色。
- 通过 `prefers-color-scheme` 跟随系统，不提供手动切换。

### 7.7 移动端

- 侧边栏默认隐藏，点击汉堡按钮以抽屉形式滑出。
- 抽屉打开时，背景内容不可滚动。
- 点击导航入口后，抽屉自动收起。
- 弹窗在移动端占满可用宽度。
- 抽屉收起时侧边栏设为 `visibility: hidden`，键盘 Tab 不会进入不可见的导航。
- 抽屉打开时焦点移到关闭按钮，收起时归还给汉堡按钮。
- 主要点击区域不小于 40px（移动端汉堡按钮 44px）。

### 7.8 状态与反馈

- 加载态：数据返回前渲染骨架卡片，骨架延迟 0.18s 淡入，本地数据秒回时不会闪一下。
- 空态：当前列表没有条目时展示「暂无内容」面板，并说明补内容的做法。
- 错误态：`data.json` 读取失败时展示具体原因（`file://` 协议、404、其他 HTTP 错误）与「重试」按钮；
  重试期间按钮禁用并显示「重试中…」。
- 可点击元素统一提供 hover、active、focus-visible 与 disabled 四种状态，焦点环为 2px 主色描边。
- 过渡时长控制在 0.15–0.25s，并遵循 `prefers-reduced-motion`：系统开启减弱动效时关闭动画。

### 7.9 可访问性

- 每个视图通过 `role="status"` 的隐藏区域播报「Prompts，共 N 条，M 个分类」，列表容器不再整体朗读。
- 分组标题是 `button`，带 `aria-expanded` 与 `aria-controls`，键盘可折叠或展开分组。
- 分类导航项高亮时带 `aria-current="true"`。
- 标题层级为 h2（视图名）→ h3（分组名）→ h4（卡片标题）。分组名包在 h3 里、
  h3 再包 button：`button` 的内容模型只允许短语内容、塞不进 h3，所以方向反过来。
- 分组配色分两档：`--group-accent` 只用于非文字元素（色条、圆点、边框），
  文字一律用 `--group-accent-text`。同一明度无法同时满足装饰与文字两种对比度要求，
  实测取一档时浅色主题有 4 个色相低于 WCAG AA 的 4.5:1。
- 弹窗打开时锁定页面滚动、焦点移到关闭按钮，Tab 在弹窗内循环，关闭后焦点归还触发它的卡片。
- 弹窗正文容器带 `tabindex="0"`，长正文可以用键盘滚动，不会卡在关闭按钮上。
- 搜索框有 `aria-label`，搜索结果条数通过 `role="status"` 播报。
- 详情弹窗的「复制链接」提供可分享的单条地址；地址只包含编码后的内容 ID，不含用户数据。
- 主按钮与当前导航的文字对比度按 WCAG AA 校验。暗色主题为按钮单独使用 `--accent-bg`，
  激活导航使用 `--accent-on-soft`：直接把亮蓝当背景或文字会低于 4.5:1。
- 当前视图的导航项带 `aria-current="page"`。
- 卡片标题保持 `h4` 语义，位于分组标题 `h3` 之下，便于按标题跳转。

### 7.10 搜索与单条深链

- 搜索框 `#search` 位于内容区标题行；输入事件做 120ms 防抖，过滤当前视图。
- `matchesQuery()` 在标题、分类、简介和正文中做不区分大小写的子串匹配；空查询不过滤。
- 无匹配时展示「没有匹配的内容」；清空搜索后恢复列表。
- 深链格式为 `#/prompts/<encodeURIComponent(id)>` 或 `#/skills/...`。
- 打开弹窗时用 `history.replaceState` 写入 hash；关闭时仅在 hash 仍指向当前条目时清空。
- 首次加载完成后由 `openHashTarget()` 解析 hash：切换视图、清空搜索词并打开对应条目；
  hash 无效时正常展示列表。
- 监听 `hashchange`，同一页面内点击深链或修改 hash 时同步打开/关闭弹窗。

### 7.11 依赖

- marked v18.0.11 与 DOMPurify 3.4.17 以本地文件形式放在 `public/vendor/`，
  页面通过相对路径引用，不访问外部网络。
- DOMPurify 的许可证见 `public/vendor/DOMPurify-LICENSE.txt`。

## 8. 本地开发与预览

前置条件：本机已安装 Python 3。

操作步骤：

1. 按第 4 节格式编辑 `content/` 下的 Markdown 文件。
2. 运行 `python3 build.py`。预期结果：`public/data.json` 更新。
3. 运行 `bash scripts/restart.sh`。预期结果：浏览器访问 `http://localhost:8001` 可预览站点。
   停止服务运行 `bash scripts/stop.sh`。端口只在 `scripts/config.sh` 定义，两个脚本共用。
4. 预览通过后，提交并推送。预期结果：GitHub 仓库 main 分支包含本次修改。

说明：预览必须通过 HTTP 访问，直接双击打开 `index.html` 时，浏览器会因 `file://` 协议禁止读取 `data.json`。

说明：`public/data.json` 是构建产物，已加入 `.gitignore`，不随提交进入仓库。
本地与服务器都在拉取代码后自行运行 `python3 build.py` 生成，因此提交时只需关注 `content/` 下的内容变更。

## 9. 测试

测试使用 Python 标准库 `unittest`，不引入第三方依赖。

- `tests/test_build.py`：构建脚本的单元测试（含 `main()` 失败关闭）。
- `tests/test_frontend.py`：前端静态一致性检查（id / class / CSS / 点击区域 / 弹窗可聚焦）。
- `tests/test_grouping.py`：app.js 分组逻辑的单元测试。
- `tests/test_render.py`：app.js 渲染链路测试（`tests/dom_stub.js` 提供最小 DOM 桩）。
- `tests/test_contrast.py`：关键配色的 WCAG 对比度回归。
- `tests/test_scripts.py`：预览脚本语法与端口配置检查。
- `tests/test_docs.py`：文档间的相对链接、四类真相文件、章节编号唯一性检查。

测试覆盖：

- frontmatter 解析：正常字段、缺失必填字段、未知键（skill）。
- 标题取自文件名：prompt 与 skill 均如此，skill frontmatter 里的 `title` 被忽略。
- prompt 简介提取：正文第一行、去掉行首 `#`、跳过开头空行、空正文。
- prompt 残留 frontmatter 时报错。
- skill 字段输出：title、intro、url、category。
- 子目录采集：递归收集、分类取值、嵌套分类、顶层文件分类为空。
- 内容 ID：不同分类下的同名文件均被保留，跨类型 ID 重复时报错。
- 构建失败：content 目录缺失、两个 kind 目录都不存在、kind 目录存在但无 Markdown、
  解析错误，均返回 1 且不覆盖已有 `data.json`。
- `data.json` 输出：结构完整、UTF-8 编码、中文不转义。

前端静态检查覆盖：

- `app.js` 里用到的 `#id` 选择器都存在于 `index.html`。
- `index.html` 里 `aria-labelledby` 等属性引用的 id 都存在。
- `app.js` 生成或切换的 class 都在 `style.css` 中有样式（JS 专用状态钩子登记在 `UNSTYLED_HOOKS` 中）。
- `style.css` 大括号配对，且用到的自定义属性都已声明。
- 主要点击区域的最小尺寸（按钮、分类 chip、分组标题、导航项）≥40px。
- 弹窗正文容器可聚焦（`tabindex="0"`）。
- 搜索框与 DOMPurify / marked 两个本地 vendor 脚本都在页面中。

分组逻辑覆盖（`tests/test_grouping.py`）：

- 从 `app.js` 原文中抽取 `hueFor` / `compareItems` / `groupItems` / `isGrouped` 四个纯函数，
  拼上最小样板交给 node 执行后断言。中文排序依赖 `Intl.Collator('zh')`，Python 标准库没有
  对等实现，因此在 Python 侧不重写排序规则。
- 覆盖：空列表、全是未分类时不分组、嵌套目录的显示名、分组按拼音排序、组内按标题排序、
  未分类沉底、条目不重不漏、配色在色板内不撞色且对同名分类稳定。
- 另有一组针对当前 `public/data.json` 的回归断言（数据文件缺失时自动跳过）。
- 本机没有 node 时整组测试跳过，不影响其余测试。

渲染链路覆盖（`tests/test_render.py` + `tests/dom_stub.js`）：

- 用最小 DOM 桩执行 `app.js`，断言分组数量与顺序、标题层级、条数、两处导航、折叠与展开、
  点击分类跳转、滚动高亮、平铺视图、切换视图。
- 详情弹窗覆盖四种组合：prompt（正文 + 复制）、skill 有正文有链接、skill 有正文无链接、
  skill 无正文。断言的是按钮构成与正文有无，而不是「弹窗打开了」。
- 补充覆盖空态、错误态、骨架态、抽屉开合、Esc 关闭、弹窗关闭后的焦点归还。
- 补充覆盖搜索过滤、无结果提示与清空恢复，以及深链打开与关闭后清空 hash。
- 补充覆盖 Markdown 渲染的消毒链路：`<script>` 被移除，正文保留。
- 断言里的总量与分组数从 `data.json` 推导，不写死条数；桩的 `eq` 对 DOM 元素输出
  `标签.类名` 形式的描述，避免元素双向引用把失败信息吞成循环引用错误。
- 桩刻意还原两条浏览器契约：脱离文档的元素 `offsetHeight` 为 0；自身或祖先 `hidden` 的元素
  同样为 0。瀑布流的「放进最短列」整个建立在这两条之上，桩不还原就测不出
  「卡片全堆进第一列」这类缺陷——列还在、卡片也在，只有分布是错的。
- 反向验证过：把修复回退成旧顺序，这套测试立刻报错。
- 每条检查在 Python 侧以 `subTest` 单独报告，一处失败不影响其余结果。
- 本机没有 node 时整组测试跳过，不影响其余测试。

浏览器验收：用 Chromium（Playwright）在 1440×900 浅色/深色与 390×844 移动端各跑一次
axe-core 的 WCAG 2 A/AA 扫描；同时手工确认搜索、深链、复制链接、弹窗与分列表现。
axe 在浅色、深色与移动端均为 0 violations；配色回归另有 `tests/test_contrast.py` 兜底。

详细的缺陷记录与取舍见 `docs/变更与审查记录.md`。

运行方式：

```bash
python3 -m unittest discover tests
```

前端不引入测试框架。上述静态检查用于拦截重构中失手的 id / class 改名，
交互与视觉表现仍按产品设计文档第 8 节的验收标准手工验证。
